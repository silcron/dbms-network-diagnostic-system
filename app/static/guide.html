STUDY GUIDE

DBMS 접속 진단 통신 시스템 이해하기

이 문서는 프로그램이 왜 필요한지, 어떤 구조로 통신하는지, 그리고 OSI 7계층을 어떻게 표현하는지 이해하기 위한 학습 자료입니다.

1. 핵심 개념

데이터베이스(DB)

회원, 주문, 상품처럼 서비스에 필요한 데이터를 체계적으로 저장하는 공간입니다.

DBMS

데이터베이스를 저장·조회·수정·권한 관리하는 소프트웨어입니다. 이 프로그램의 점검 대상은 MariaDB입니다.

MariaDB

표 형태의 데이터를 관리하는 관계형 DBMS입니다. 진단 서버는 MariaDB 접속과 쿼리 실행 가능 여부를 확인합니다.

SQL

DBMS에 명령을 내리는 언어입니다. SELECT 1은 DB 연결과 쿼리 처리 여부를 확인하는 간단한 점검용 명령입니다.

프로그램 목적
DB 접속 오류가 생겼을 때 네트워크 연결 실패, DB 로그인·쿼리 오류, 응답 지연을 구분해 점검 범위를 빠르게 좁히는 것입니다.

Python 웹 중계브라우저의 HTTP 요청을 받고, TCP 진단 서버에 대신 연결하는 중계 서버입니다.
TCP 진단 서버세션을 확인하고 MariaDB에 실제로 접속해 진단하는 핵심 서버입니다.
MariaDB접속·로그인·쿼리 실행 가능 여부를 점검받는 DBMS입니다.

3. 네트워크 용어와 포트

클라이언트 · 서버

클라이언트는 요청하는 쪽, 서버는 요청을 처리해 결과를 돌려주는 쪽입니다.

HTTP

브라우저와 웹 서버가 주로 사용하는 통신 방식입니다. 이 프로그램에서는 브라우저와 웹 중계 서버 사이에 사용합니다.

TCP

연결 상태와 데이터 순서를 관리해 안정적으로 전달하는 방식입니다. 웹 중계와 진단 서버 사이에 사용합니다.

IP 주소 · 포트

IP 주소는 통신 대상 PC의 주소이고, 포트는 그 PC 안에서 통신할 프로그램을 구분하는 번호입니다.

JSON · UTF-8

JSON은 데이터를 텍스트 구조로 표현하는 형식이고, UTF-8은 한글과 문자를 전달하기 위한 인코딩 방식입니다.

세션

현재 어떤 연결에서 요청이 왔는지 구분하고, 요청 순서와 연결 종료를 관리하는 정보입니다.

포트사용 구간
8080브라우저 ↔ Python 웹 중계 서버의 HTTP 통신
9090Python 웹 중계 서버 ↔ TCP 진단 서버의 TCP 통신
3307TCP 진단 서버 ↔ MariaDB의 DB 통신

4. 실제 동작 순서

  1. 사용자가 브라우저에서 진단 시작
    브라우저가 웹 중계 서버에 HTTP 요청을 보냅니다.
  2. 웹 중계 서버가 TCP 진단 서버에 연결
    웹 중계 서버가 TCP 9090 포트로 진단 서버와 통신합니다.
  3. 진단 서버가 세션을 확인
    연결 상태를 관리하고 정상적인 진단 요청인지 확인합니다.
  4. LIVE 모드에서 MariaDB 점검
    MariaDB 연결, 로그인, SELECT 1 실행, 응답 시간 측정을 수행합니다.
  5. 상태 결과 반환
    정상은 NORMAL, 확인 필요는 WARNING, 연결 실패는 DOWN으로 브라우저에 표시합니다.
DEMO 모드
발표와 테스트를 위해 NORMAL·WARNING·DOWN 상태를 재현합니다. 실제 DB 연결을 증명하는 기능은 LIVE 모드입니다.

5. OSI 7계층 적용

계층계층의 역할이 시스템의 계층별 구현 내용
7 응용사용자 요청·응답 처리브라우저에서 DB 진단을 요청하고 서버가 DB 점검 결과를 반환합니다.
6 표현데이터 형식 변환진단 요청·결과를 JSON·UTF-8 형식으로 변환합니다.
5 세션연결 상태 관리진단 연결 상태를 관리하고 요청을 확인합니다.
4 전송안정적인 데이터 전달TCP 9090 포트로 진단 서버와 연결합니다.
3 네트워크통신 대상 지정127.0.0.1 IP 주소로 같은 PC의 진단 서버 위치를 지정합니다.
2 데이터링크같은 네트워크 안의 프레임 전달현재는 루프백 가상 경로이며, LAN 연결 시 이더넷 프레임이 적용됩니다.
1 물리신호 전송현재는 루프백 가상 경로이며, LAN 연결 시 Wi-Fi 또는 케이블 신호가 적용됩니다.
중요한 사실
현재는 브라우저·웹 중계·진단 서버·MariaDB가 같은 PC에서 실행되므로 2·1계층은 실제 랜선이나 Wi-Fi가 아닌 루프백 가상 경로입니다. 진단 서버를 다른 PC로 옮겨 LAN으로 연결하면 이더넷·Wi-Fi·케이블 구간이 실제로 적용됩니다.

6. 발표용 스크립트

1페이지: 프로그램 소개와 클라이언트–서버 아키텍처
발표 스크립트 안녕하세요. 제가 만들고자 하는 프로그램은 DBMS 접속 진단 통신 시스템입니다. AI 발전으로 데이터의 중요성이 커지면서, 데이터를 관리하는 DBMS의 안정적인 운영도 중요해지고 있습니다. 그래서 DB 접속 오류가 발생했을 때 네트워크 문제인지 DB 문제인지 빠르게 확인할 수 있는 시스템을 만들고자 했습니다. 구조는 그림을 왼쪽에서 오른쪽으로 보시면 됩니다. 사용자가 브라우저에서 진단을 시작하면, 브라우저는 Python 웹 중계 서버에 HTTP 요청을 보냅니다. 웹 중계 서버는 TCP 9090 포트를 사용해 TCP 진단 서버에 요청을 전달합니다. 진단 서버는 MariaDB에 실제로 연결해 로그인과 SELECT 1 쿼리를 실행하고, 접속 상태와 응답 시간을 확인합니다. 이후 결과를 브라우저 화면에 NORMAL, WARNING, DOWN 상태로 표시합니다. 구현에는 HTML, CSS, JavaScript, Python의 HTTP 서버와 소켓 통신, PyMySQL, MariaDB를 사용했습니다.
2페이지: OSI 7계층 적용
발표 스크립트 이 프로그램은 DB 진단 요청과 응답 과정을 OSI 7계층에 맞춰 표현했습니다. 응용 계층에서는 브라우저가 DB 진단을 요청하고 서버가 결과를 반환합니다. 표현 계층에서는 요청과 결과를 JSON과 UTF-8 형식으로 처리하고, 세션 계층에서는 진단 연결 상태를 관리합니다. 이후 전송 계층에서는 TCP 9090 포트를 통해 데이터를 전달하고, 네트워크 계층에서는 IP 주소를 통해 진단 서버를 지정합니다. 현재는 같은 PC에서 실행하므로 데이터링크 계층과 물리 계층은 루프백 가상 경로로 동작합니다. 하지만 서버를 다른 PC로 확장하면 이더넷, Wi-Fi, 케이블을 사용하는 실제 LAN 환경까지 적용할 수 있습니다. 이 시스템은 네트워크 연결 실패, DB 로그인·쿼리 오류, 응답 지연을 구분해 DB 접속 장애의 원인 확인을 지원합니다. 감사합니다.
